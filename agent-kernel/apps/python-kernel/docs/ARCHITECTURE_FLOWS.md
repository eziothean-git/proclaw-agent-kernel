## 二、SEE-ACT-UPDATE 循环详解

### 2.1 单次循环流程

```
┌─────────────┐
│    START    │
└──────┬──────┘
       │
       ▼
┌────────────────────────────┐
│  STEP 1: SEE (观察)         │
│                            │
│  1.1 从 Event Log 获取     │
│      最近事件               │
│                            │
│  1.2 选择 Artifacts        │
│      (按Phase规则)          │
│                            │
│  1.3 组装 Working Set      │
│      (Token预算内)          │
└──────┬─────────────────────┘
       │
       ▼
┌────────────────────────────┐
│  STEP 2: ACT (行动)         │
│                            │
│  2.1 调用 LLM              │
│      (Working Set → Prompt)│
│                            │
│  2.2 解析输出              │
│      (YAML/JSON/启发式)     │
│                            │
│  2.3 识别意图              │
│      - TOOL_CALL           │
│      - PHASE_TRANSITION    │
│      - FINAL_ANSWER        │
│      - ...                 │
└──────┬─────────────────────┘
       │
       ▼
┌────────────────────────────┐
│  STEP 3: UPDATE (更新)      │
│                            │
│  CASE 1: TOOL_CALL         │
│  ├─ 3.1 记录 TOOL_CALL 事件│
│  ├─ 3.2 提交 Coordinator   │
│  ├─ 3.3 执行 (Local/Remote)│
│  ├─ 3.4 记录 TOOL_RESULT   │
│  └─ 3.5 更新 Artifacts     │
│                            │
│  CASE 2: PHASE_TRANSITION  │
│  ├─ 3.1 验证转换有效性     │
│  ├─ 3.2 记录 PHASE_CHANGE  │
│  └─ 3.3 更新 current_phase │
│                            │
│  CASE 3: FINAL_ANSWER      │
│  └─ 3.1 构建 AgentOutput   │
│      并返回                │
└──────┬─────────────────────┘
       │
       ▼
┌──────────────┐
│   END?       │──NO──┐
│ (max_steps   │      │
│  or complete)│      │
└──────┬───────┘      │
      YES             │
       │              │
       ▼              │
┌──────────────┐      │
│   RETURN     │      │
│  AgentOutput │      │
└──────────────┘      │
                      │
       ┌──────────────┘
       │
       ▼
  [继续循环]
```

## 三、Working Set 构建流程

```
┌───────────────────────────────────────────────────────┐
│                 WorkingSetBuilder.build()             │
└───────────────────────────────────────────────────────┘
                          │
                          ▼
┌───────────────────────────────────────────────────────┐

│    slot_rule = slot_rules[phase]                      │

└────────────────┬──────────────────────────────────────┘
                 │
                 ▼
┌───────────────────────────────────────────────────────┐
│ 2. 选择 Artifacts                                     │
│    - 过滤: slot_type 在允许列表中                      │
│    - 过滤: priority >= threshold                      │
│    - 排序: 按 priority 降序                           │
│    - 选择: 前 max_slots 个                            │
└────────────────┬──────────────────────────────────────┘
                 │
                 ▼
┌───────────────────────────────────────────────────────┐
│ 3. 选择 Observations                                  │
│    - 确定范围: lookback_steps                         │
│    - 过滤: event_type 在 priority 列表中               │
│    - 排序: 时间倒序(最近优先)                          │
│    - 选择: 前 max_count 个                            │
└────────────────┬──────────────────────────────────────┘
                 │
                 ▼
┌───────────────────────────────────────────────────────┐
│ 4. 获取上一步结果                                     │
│    - 查找最近 TOOL_RESULT / OBSERVATION               │

                 │
                 ▼
┌───────────────────────────────────────────────────────┐

└────────────────┬──────────────────────────────────────┘
                 │
                 ▼

└────────────────┬──────────────────────────────────────┘
                 │
                 ▼
         ┌───────┴───────┐
         │ > max_total?  │
         └───────┬───────┘
            YES /   \ NO
               /     \
              ▼       ▼
┌─────────────────┐  ┌──────────────┐
│ 7. 截断         │  │ 8. 返回      │
│    - 优先截断   │  │    WorkingSet│
│      Observations│  └──────────────┘

└─────────────────┘
```

## 七、Phase 切换流程

### 7.1 自主切换

```
┌──────────────────────────────────────────────────────┐
│                  Agent Thread                        │
│                                                      │
│  Current Phase: EXPLORE                              │
│                                                      │
│  Step N:                                             │
│  1. Build Working Set (with EXPLORE rules)           │
│  2. LLM generates output:                            │
│                                                         
│     ```yaml                                           
│     intent: phase_transition                         │
│     from_phase: explore                              │
│     to_phase: execute                                │
│     reason: "Gathered enough context"                │
│     ```                                               
│                                                      │
│  3. Parser identifies PHASE_TRANSITION intent        │
│                                                      │
│  4. _handle_phase_transition():                      │
│     - Validate: from_phase == current_phase? ✓      │
│     - Log: PHASE_CHANGE event                        │
│     - Update: current_phase = EXECUTE               │
│                                                      │
│  Next Step N+1:                                      │
│  1. Build Working Set (with EXECUTE rules) ←不同规则 │
│  2. ...                                             │
└──────────────────────────────────────────────────────┘
```

### 7.2 强制切换（上层干预）

```
┌──────────────────────────────────────────────────────┐
│ 上层调用:                                            │
│ scheduler.update_thread_phase(task_id, "execute")   │
└────────────────┬─────────────────────────────────────┘
                 │
                 ▼
┌──────────────────────────────────────────────────────┐
│ Scheduler:                                          │
│ 1. 查找 AgentThread                                  │
│ 2. 调用 agent.apply_context_update({"phase": "execute"})│
└────────────────┬─────────────────────────────────────┘
                 │
                 ▼
┌──────────────────────────────────────────────────────┐
│ AgentThread.apply_context_update():                  │
│                                                      │
│ 1. 检查 updates["phase"]                             │
│ 2. if "phase" in updates:                           │
│    - new_phase = Phase(updates["phase"])             │
│    - 记录 PHASE_CHANGE 事件 (external)              │
│    - current_phase = new_phase                       │
│    - log: "Phase updated via external request"       │
│                                                      │
│ 3. if "max_steps" in updates:                       │
│    - max_steps = updates["max_steps"]                │
│                                                      │
│ (下次循环使用新 Phase 的规则)                        │
└──────────────────────────────────────────────────────┘
```

## 十、性能考虑

### 10.1 Token 预算分配

```
Working Set Token Budget (4000 total):
├─ Immutable Context:    500 (12.5%)
├─ Observations:        1500 (37.5%)
├─ Artifacts:           1500 (37.5%)
└─ Notes/Other:          500 (12.5%)
```

### 10.2 Event Log 增长

- Event Log 无限增长（存储在内存/持久化）
- Working Set 保持固定大小
- 定期导出和归档 Event Log

### 10.3 截断策略

当超出 Token 预算时：
1. 首先截断 Observations（保留最少数量）
2. 其次截断 Artifacts（按优先级）
3. 始终保留 Immutable Context
